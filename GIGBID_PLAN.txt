and handle client conversations. A human approves EVERYTHING that leaves the system.

Marks (100): A MCP tool layer 20 | B Advanced RAG 20 | C LangGraph multi-agent 25 |
D Web UI 15 | E Production engineering 10 | Portfolio+R&D report 10.
Viva multiplier 0..1.0 -> owner MUST understand the system (see docs/VIVA_PREP.md [SIDEWAY-ok]).

Non-negotiables R1..R10:

    Ranking, Indexing, Agentic(V8 or V9))

5. TECH STACK & HOW TO ATTEMPT (top level)
---------------------------------------------------------------------
Language/runtime : Python 3.11+ (uv, pinned lockfile) ; Node 20+ for web.
Agents           : LangGraph (StateGraph, Send, interrupt, Postgres checkpointer, Store)
                   + langchain-mcp-adapters (MultiServerMCPClient, Streamable HTTP).
MCP              : official `mcp` Python SDK (FastMCP) for all 3 own servers; 3rd party:
                   official Upwork MCP (live) + GitHub MCP (repo ingest).
LLMs             : profile "open" default. Local: Ollama (Qwen3 4B/8B router tier;
                   gpt-oss-20b / Qwen 27B 4-bit writer tier if GPU). Hosted open models for
                   the public deployment (Groq / OpenRouter / Together). Profile "paid"
                   optional. All via OpenAI-compatible client; model per node in config.
Embeddings       : BGE-M3 or nomic-embed-text (CPU); reranker bge-reranker-v2-m3 (CPU,
                   sentence-transformers CrossEncoder). Chosen by eval.
Vector/lexical   : Postgres + pgvector (one vector store, one fewer service) + BM25
                   (rank_bm25 / Postgres FTS). In-memory backend for unit tests.
Backend          : FastAPI, Pydantic v2, SQLAlchemy 2 + Alembic, SSE streaming, JWT/cookie
                   sessions, Fernet-encrypted OAuth token store, tenant-scoped queries.
Queue/worker     : Arq on Redis (asyncio-native, fits LangGraph async). Idempotency keys.
Frontend         : Next.js (App Router) + TypeScript + Tailwind; TS client generated from
                   OpenAPI (openapi-typescript); Playwright for e2e.
Observability    : Arize Phoenix (OpenTelemetry/OpenInference; single container; self-hosted)
                   - chosen over Langfuse v3 to keep compose light on free hosts. ADR.
Evals            : custom runners + RAGAS-style metrics where useful; calibrated LLM judge.
CI               : GitHub Actions (ci.yml, eval.yml with thresholds).
Deploy           : docker compose locally; public host TBD with owner (see STATE).

Approach principles
 - Ports & adapters: graph never knows which marketplace is used.
 - Data over code: policy rules, costs, thresholds, model routing, prompts in config/md.
 - Typed hand-offs everywhere a later node decides something.
 - Three separations: State (per job) / Execution trace (audit) / Long-term memory
   (promoted only).
 - Measure first: no number in README/report without a file in evals/results/.
 - Safe by construction: write tools only reachable after an approval token produced by the
   interrupt resume; dry_run first; idempotency keys derived from (user, job, draft hash).
 - Degrade gracefully: MCP down -> UI banner, queue work, auto-recover.

6. SIGNATURE EXTENSION (decision, revisable)
---------------------------------------------------------------------
Chosen: X2 Proposal experiments (A/B strategies in GigSim with significance test on reply
rate) - the only option fully measurable offline in the simulator, strongest "real finding"
for the write-up, and directly useful later (learn which opening/structure wins).
Design: strategy registry in config (e.g. "evidence-first" vs "question-first opener"),
deterministic assignment by hash(job_id), per-strategy outcomes in outcome memory,
two-proportion z-test / Fisher exact in analytics screen.
Post-assignment add-ons (not graded): X6 live mode on owner's real Upwork account (already
enabled by the adapter), X3 portfolio builder from GitHub.
If the owner prefers another extension, only Phase 9.1 changes.
